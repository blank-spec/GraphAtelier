# Graph Atelier

Приложение для исследования алгоритмов Дейкстры и Уоршелла на ориентированных графах. Реализация: C++20, Qt Quick и QML. Исходные наборы включают 20 вариантов; при запуске выбран вариант 18.

Интерфейс использует полностью тёмную графитовую палитру с синими, фиолетовыми и багровыми акцентами. Цвета заданы в `qml/Theme.qml`.

## Запуск приложения

Готовая сборка Windows x64 находится в каталоге `app`. Для запуска откройте `app/GraphAtelier.exe`. Установка Qt не требуется. EXE должен находиться вместе с поставляемыми DLL и подкаталогами.

Папка `app` содержит EXE и необходимые библиотеки Qt, плагины, QML-модули, среду выполнения MinGW и `qt.conf` с относительными путями. Для запуска готовой сборки Qt, CMake, компилятор, Excel и Python устанавливать не нужно. Инструменты разработки требуются только для сборки из исходников.

После запуска отображается результат Дейкстры для источника `v1` и цели `v14`. Кнопка «Воспроизвести» запускает пошаговый просмотр с начального состояния.

## Сборка из исходников

Требуются CMake 3.21 или новее, компилятор с поддержкой C++20 и Qt 6.5 или новее с модулями Quick, Quick Controls 2 и SVG. Сборка проверена на Windows x64 с Qt 6.11.0 MinGW и GCC 13.1.

При настроенном окружении компилятора:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="путь/к/Qt/kit"
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Для Windows MinGW также предусмотрен скрипт:

```powershell
.\tools\build.ps1 -QtKit "D:/Qt/6.11.0/mingw_64" -CompilerBin "D:/Qt/Tools/mingw1310_64/bin" -CMakeBin "D:/Qt/Tools/CMake_64/bin" -NinjaBin "D:/Qt/Tools/Ninja" -Deploy
```

Параметр `-Deploy` создаёт переносимую сборку в `app`. В Qt Creator проект открывается через `CMakeLists.txt`.

## Входные данные

Матрицы извлечены из файлов «Алгоритм Дейкстры 20 вариантов.xlsx» и «Алгоритм Уоршелла 20 вариантов.xlsx». Дейкстра использует графы из 15 вершин, Уоршелл — из 10 вершин.

Строка матрицы соответствует началу дуги, столбец — её концу. Ноль означает отсутствие дуги. Взвешенный граф содержит только положительные веса. Обозначение `∞` используется для недостижимой вершины.

Данные встроены в ресурсы приложения; Excel и Python при запуске не используются. Файл `data/provenance.json` содержит имена исходных листов, диапазоны ячеек и контрольные суммы SHA-256. Для повторного извлечения матриц используется стандартная библиотека Python:

```powershell
python tools/extract_data.py --dijkstra "путь/Алгоритм Дейкстры 20 вариантов.xlsx" --warshall "путь/Алгоритм Уоршелла 20 вариантов.xlsx"
```

## Алгоритмы

### Дейкстра

Начальная дистанция источника равна 0, остальные дистанции равны бесконечности. На каждой итерации выбирается незафиксированная вершина с минимальной дистанцией. После её фиксации выполняется релаксация исходящих дуг. Массив предков используется для восстановления маршрутов. При равных дистанциях выбирается вершина с меньшим номером.

Для матричного представления используется прямой поиск минимума: время O(V²), рабочая память O(V) без учёта исходной матрицы и снимков состояния, сохраняемых для визуализации.

### Уоршелл

Для каждой промежуточной вершины `k` обновляется достижимость:

```text
R[i][j] = R[i][j] OR (R[i][k] AND R[k][j])
```

Режим A+ учитывает пути длины не меньше одного ребра: единица на диагонали появляется при наличии цикла. Режим A* дополнительно включает пути длины 0 и устанавливает единицы на диагонали до начала итераций. По умолчанию используется A+.

Достижимость хранится во внутренних блоках по 64 бита. Для вершины, которая достигает `k`, строка объединяется со строкой `k` побитовым OR; изменённые ячейки определяются по новым битам. Само ядро выполняет O(V² · ceil(V/64)) операций с блоками. Преобразование результата в обычную матрицу требует O(V²), а сохранение всех снимков по-прежнему требует O(V³) времени и памяти.

### Быстрый расчёт и повторное использование

Для визуализации по умолчанию сохраняются все шаги. `algo::dijkstra(..., algo::TraceMode::ResultOnly)` вычисляет расстояния и предков без истории; этот режим используется при экспорте маршрутов от всех источников. `algo::transitiveClosure(...)` возвращает только итоговое замыкание без снимков.

Движок хранит до 15 решений Дейкстры и два режима Уоршелла для текущего варианта. Смена источника не пересчитывает Уоршелла, смена A+/A* не пересчитывает Дейкстру, повторный выбор параметров использует кэш. При смене варианта кэш очищается.

В Release-сборке с тестами доступен `build/algorithm_benchmark.exe`. Он выполняет прогрев и 31 серию измерений, выводит медиану и P95 средних значений серий в CSV. Проверки `ctest` включают независимые эталоны, точное сравнение шагов Уоршелла, границы 64-битных блоков, граф на 1000 вершин и работу кэша. Текущие замеры приведены в `results/benchmarks/GraphAtelier-benchmarks.md`.

## Управление

- Переключатель алгоритма выбирает Дейкстру или Уоршелла.
- Номер варианта задаёт пару исходных графов.
- Поля «От» и «до» задают источник и цель для Дейкстры. Цель также выбирается нажатием на вершину или строку таблицы.
- Кнопки воспроизведения, шага и ползунок позволяют просматривать вычисления в обоих направлениях.
- Перетаскивание вершины изменяет её положение. Кнопка сброса над графом восстанавливает круговую раскладку.
- Кнопка разворачивания над графом или `F11` включает полноэкранный просмотр графа. Шкала шагов, воспроизведение, скорость и настройки отображения остаются доступны. `Esc`, `F11` или кнопка «Выйти» возвращают прежний режим окна. Текущий шаг, воспроизведение и расположение вершин сохраняются.
- Переключатель всех дуг показывает исходный орграф поверх дерева кратчайших путей. Фоновые дуги приглушены; веса выделенных дуг отображаются поверх графа.
- Синий цвет обозначает выбранный маршрут, фиолетовый — активное состояние алгоритма, багровый — выбранную цель. В матрице Уоршелла отдельно выделяются связи, добавленные на текущем шаге.
- Переключатель анимаций отключает переходы цветов матрицы и движение маркеров маршрута.

Клавиши: `Space` — пуск/пауза, `←` / `→` — шаг, `Home` / `End` — начало/итог. Перемещение между элементами интерфейса выполняется клавишей `Tab`; внутри матрицы стрелки перемещают фокус между ячейками.

## Результаты

Кнопка экспорта сохраняет окончательные результаты в выбранный каталог независимо от текущего положения шкалы шагов. Для варианта 18 результаты также сохранены в `results/variant18`. Текущие замеры: `results/benchmarks/GraphAtelier-benchmarks.md`.

`warshall_reachability.csv` содержит итоговую матрицу 10×10. Файлы `dijkstra_all_distances.csv` и `dijkstra_all_routes.csv` содержат расстояния и маршруты для всех 225 пар вершин. Файл `dijkstra_selected_source.csv` содержит пути от выбранного источника. Исходные матрицы сохранены в `dijkstra_input.csv` и `warshall_input.csv`; последовательность состояний Уоршелла — в `warshall_steps.json`.

Две визуализации представлены файлами `dijkstra_graph` и `warshall_graph` в форматах PNG и SVG. Первая показывает дерево кратчайших путей с выбранным маршрутом, вторая — исходный орграф и итоговую матрицу достижимости. Размер PNG — 1800×1100. SVG поддерживает масштабирование без потери чёткости. Краткое описание расчёта и таблица маршрутов находятся в `RESULTS.md`.

CSV используют кодировку UTF-8 и разделитель «запятая». При импорте в Excel следует явно выбрать эти параметры.

В варианте 18 взвешенный граф содержит 100 дуг, невзвешенный — 58. Итоговое замыкание Уоршелла содержит 100 достижимых пар, включая диагональ. Начальная вершина по умолчанию — `v1`; её можно изменить в интерфейсе.

Экспорт из командной строки:

```powershell
.\app\GraphAtelier.exe --export "путь/к/каталогу/результатов"
```

## Проверка корректности

Тесты охватывают все 40 матриц из Excel и 100 случайных графов с фиксированным seed. Дистанции Дейкстры сравниваются с независимым алгоритмом Флойда, замыкание Уоршелла — с обходом в ширину. Проверяются концы и стоимость маршрутов, недостижимые вершины, одиночная вершина, отклонение отрицательных весов, цикл в массиве предков и отметки новых связей. Проверки выполняются в том числе в Release-сборке.

Для измерения первого и повторных переключений можно включить диагностическую сборку:

```powershell
cmake -S . -B build -DATELIER_UI_CAPTURE=ON
cmake --build build --parallel
.\build\GraphAtelier.exe --capture "build/performance" --benchmark-switch
```

Файл `switch-benchmark.json` содержит время обработки переключения и время до первого отображённого кадра. В обычной сборке параметр `ATELIER_UI_CAPTURE` отключён.

## Структура проекта

- `src/algorithms.*` — алгоритмы без зависимости от Qt.
- `src/engine.*` — состояние приложения, снимки вычислений и экспорт.
- `src/graphitem.*` — интерактивная визуализация и сохранение изображений.
- `src/main.cpp` — запуск приложения.
- `qml/` — интерфейс и собственные компоненты управления.
- `tests/` — проверки корректности.
- `tools/` — сборка и извлечение матриц.

Лицензии используемых библиотек и шрифта находятся в `licenses/` и `data/OFL-Manrope.txt`.
